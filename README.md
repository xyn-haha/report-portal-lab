## 一、靶场定位

这是一套**链式**靶场，核心教学思想只有一句话：

> **攻击者必须先取得对某个"持久化业务字段"的控制权，该字段随后被不安全地求值，
> 才可能触发命令执行；缺少前面任何一个前置条件，执行环节都不可能被打通。**

靶场刻意**不提供**任何一步到位的入口。想拿到最终结果，必须真正理解整条链路的因果关系：

```
① 侦察            首页 HTML 注释里藏着部署期遗留的调试入口线索
② 未授权信息泄露   调试入口未鉴权，泄露数据文件位置与内部接口名称
③ 路径遍历        报表预览接口有明文过滤，但存在一次多余的解码 → 可绕过；
                  读取范围被限制在应用目录内的数据文件 → 拿到数据库
④ 取得可控字段     从数据库中读到"内部签名密钥"，理解配置更新接口的调用约定，
                  并用它把某条报表的"预览表达式"字段改成自己想要的内容
⑤ 条件触发        再带签名调用内部执行接口，后端才会把该字段送进表达式求值 → 命令执行
⑥ 两个验证值      「用户层」验证值放在数据库里（拿到数据文件即可见）；
                  「高权限层」验证值在容器高权限目录中（必须走到第 ⑤ 步才能读到）
```

技术栈：**Python 3 + Flask + SQLite**，容器镜像基于 `python:3.12-alpine`，体积很小。

## 二、目录结构

```
靶场/
├── app.py                 Web 应用（全部路由与核心逻辑）
├── init_db.py             数据库初始化脚本（首次启动自动执行）
├── entrypoint.sh          容器启动脚本（准备结果目录 + 初始化 + 启动应用）
├── Dockerfile             镜像构建文件
├── requirements.txt       依赖（仅 Flask）
├── docker-compose.yml     可选的 compose 一键拉起
├── README.md              本文件（靶场说明，无提示）
├── HINT.md                新手闯关提示（每关 3 级提示，给方向不给答案）
├── SOLUTION.md            含完整答案的解题步骤（每关已折叠，别提前点开）
└── tools/                 【给学员的小工具】只需改一行
    ├── 看库.py            打开数据文件，一次列全所有表和内容
    └── 执行表达式.py       改字段 + 触发执行（改 EXPR 一行即可）
```

### 三份文档的学习路径

```
README.md    先看这个 —— 搞清楚靶场是什么、怎么启动
    ↓
HINT.md      卡住了看这个 —— 通用方法 + 每关 3 级提示（给方向，不给答案）
    ↓
SOLUTION.md  做完再看这个 —— 含完整答案（每关已折叠，不会不小心看到）
```

> `HINT.md` 里有一章【通用方法】（接口侦查四步法、读前端 4 问、卡住时的自问清单），
> **那一章比任何一关的答案都值钱** —— 它跟这个靶场无关，换任何目标都能用。

> `tools/` 里的脚本只把「算哈希、发 HTTP、解析数据库」这类机械劳动包好了，
> **不含任何关于"怎么发现漏洞"的提示** —— 那部分留给学员自己推理。

运行时自动生成：

```
/app/data/report.db        数据文件（首次启动创建）
/app/templates/            报表导出缓存目录（路径遍历的作用点）
/flag/                     结果目录（含诱饵文件）
/root/root_flag.txt        高权限层验证值
```

## 三、快速开始

### 方式一：Docker 命令行

```bash
cd 靶场
docker build -t report-portal-lab .
docker run -d --name report-portal-lab -p 127.0.0.1:8080:8080 report-portal-lab
```

### 方式二：docker compose

```bash
cd 靶场
docker compose up -d --build
```

### 方式三：不用 Docker，本地直接跑

```bash
pip install -r requirements.txt
python init_db.py
python app.py
```

### 可配置的环境变量

| 变量 | 默认值 | 说明 |
|---|---|---|
| `PORT` | `8080` | 应用监听端口（容器内端口，按需改） |
| `USER_FLAG` | 随机生成 | 用户层验证值 |
| `ROOT_FLAG` | 随机生成 | 高权限层验证值 |
| `INTERNAL_SIGN_KEY` | 随机生成 | 内部接口签名密钥 |
| `SANDBOX_READ_ROOTS` | `/flag,/root` | 沙盒允许读取的目录（跨平台本地验证时可覆盖） |

示例：本机 8080 已被占用时，改用别的宿主端口

```bash
docker run -d --name report-portal-lab -p 127.0.0.1:18080:8080 report-portal-lab
```

启动后访问：**http://127.0.0.1:8080**

> 端口已刻意绑定在 `127.0.0.1`，避免被同网段其他机器访问。

### 收尾

```bash
docker rm -f report-portal-lab
docker rmi report-portal-lab
```

## 四、验证值（flag）说明

靶场有**两个**验证值，分层设计：

| 层级 | 位置 | 取得条件 |
|---|---|---|
| 用户层 | 数据文件的系统配置表中 | 完成第 ③ 步（路径遍历拿到数据文件）即可读到 |
| 高权限层 | 容器内高权限目录的独立文件中 | **必须**完成第 ④⑤ 步（伪造签名 + 表达式求值）才能读出 |

- 两个验证值**默认随机生成**，不会打印到启动日志，需要靠漏洞自己获取；
- 如需固定值以便反复复现，可通过环境变量指定：

```bash
docker run -d --name report-portal-lab -p 127.0.0.1:8080:8080 \
  -e USER_FLAG="FLAG{my_user_flag}" \
  -e ROOT_FLAG="FLAG{my_root_flag}" \
  -e INTERNAL_SIGN_KEY="0f1e2d3c4b5a6978" \
  report-portal-lab
```

- 仅作环境自查时可执行：`docker exec -it report-portal-lab cat /root/root_flag.txt`（做题时请不要用）。

## 五、每一环的设计意图（思路提示，不给现成利用载荷）

本靶场**不提供 poc/exp**，请按下面的思路自行推导。给出的是"为什么能打通"，不是"复制哪一行"。

### 第 ① 环 · 侦察

首页是一个很简陋的报表控制台。**没有默认可用账号**（登录接口对任何输入都返回失败）。
线索不在页面上，而在**页面源码的注释里**——那是运维留下的上线前待办清单。

> 教学点：真实项目中，注释、备份文件、`.git`、错误页、调试端点，是最常见的泄露源。

### 第 ② 环 · 未授权信息泄露

从注释里找到的调试入口**未做任何鉴权**。它返回 JSON，直接告诉你有：

- 数据文件的相对路径（`data/report.db`）；
- 报表导出缓存目录（`templates/`）；
- 两个**不对外公开的内部接口**名称；
- 内部接口需要携带的请求头名称。

> 教学点：调试/健康检查类端点往往在开发期临时加上，上线后忘记关闭；它们泄露的"路径 + 接口名"正是后续链路的起点。

### 第 ③ 环 · 路径遍历（过滤了，但过滤得不彻底）

报表预览接口接收一个文件名参数。它做了两件互相矛盾的事：

1. 按**原样**检查参数里是否含有明文的上跳序列，有就拒绝；
2. 但在真正取文件之前，**又对参数做了一次 URL 解码**。

于是：对特殊字符做**两次编码**，第 1 步看到的就不是明文上跳序列，第 2 步解码后才变成真正的路径。

同时这个接口**被有意收窄**了：解析后的路径必须落在应用目录内，且扩展名必须是数据文件类型。
也就是说——**你只能读到数据文件，读不到操作系统的敏感路径**。这正是本靶场的教学边界。

> 教学点：①"先校验后解码"是典型的过滤绕过成因；②即便存在遍历，影响面也取决于读取范围是否被收窄（本靶场刻意收窄，让你聚焦在"拿到数据"而不是"乱翻文件"）。

### 第 ④ 环 · 取得可控的业务字段（关键一步）

把上一步拿到的数据文件下载下来，用任意 SQLite 工具打开，你会看到：

- 一张**系统配置表**，其中存着**内部接口的签名密钥**和**签名算法约定**（这就是必须读数据文件的原因）；
- 一张**报表定义表**，其中有一个字段是"预览表达式"，属于业务上**允许高权限用户维护、后端后续会读取使用**的值；
- 用户层验证值；
- 以及若干条**诱饵记录**（历史日志、示例值、已废弃字段），用来干扰判断。

接着你会发现：**配置更新接口需要携带一个内部签名**，而这个签名的算法和密钥，恰好都躺在你刚读到的数据文件里。
用它们自己算出一个合法签名，就能把那条件报表的"预览表达式"改成任何你想要的内容。

> 教学点：这是整条链的枢纽——**攻击者在此获得了对持久化业务数据的写入能力**。
> 注意：**普通访问者既不能直接调用执行接口，也不能直接改这个字段**，必须先读数据、理解业务结构，才能伪造出合法调用。

### 第 ⑤ 环 · 条件触发的执行环节

最后一步：再带签名去调用那个**内部报表执行接口**。

后端此时才把第 ④ 步改过的字段取出来，送进表达式求值逻辑。**只有前面全部前置条件都满足**，
这一步才会有实际效果——否则它会先后在"签名校验""报表是否存在"等环节把你的请求挡回去。

> 教学点：**"有求值点"不等于"可利用"**。真正的风险来自"该字段可被外部写入"这一前置条件。

### 第 ⑥ 环 · 沙盒边界（务必阅读）

为了让本项目可以安全地在本地反复练习，执行环节**加了简单沙盒**：

| 允许 | 禁止 |
|---|---|
| 读取结果目录内的验证值文件 | 任何写入、删除、修改系统的操作 |
| 查询当前身份等只读命令 | 下载、反弹、联网、启动服务等破坏性/外联操作 |
| 有限的数学与字符串运算 | 访问结果目录以外的任何路径 |

因此本靶场展示的是"**表达式注入导致受控执行**"这一原理，**不是**一个可以拿来打真实系统的利用工具。
沙盒中任何越界尝试都会返回明确的拒绝信息——这也是教学的一部分：
**真实世界里没有这层沙盒，所以"字段可写"这一个前置条件才如此危险。**

## 六、自查清单

做完一遍后，可以用下面的问题检验自己是否真的理解了这条链：

1. 为什么"明文过滤上跳序列 + 事后解码"会被绕过？如果只解码一次还成立吗？
2. 如果预览接口没有收窄读取范围（允许读任意路径），这条链会更短还是更长？为什么？
3. 配置更新接口的签名为什么"看起来有防护，实际等于没有"？它依赖了什么前提？
4. 如果把"预览表达式"字段改成只读（业务上不再允许修改），这条链还能走通吗？
5. 第 ⑤ 环里，后端其实做了几次校验？分别在哪一步把你的请求挡回去？
6. 沙盒挡住了哪些操作？如果没有沙盒，同一个注入点会造成什么后果？

## 七、小贴士：拉不到基础镜像时怎么办

`Dockerfile` 基于 `python:3.12-alpine`。如果本机访问 Docker Hub 受限（`docker build` 报
`failed to resolve source metadata ... dial tcp: lookup ...: no such host`），可以先用可用的镜像加速器
把基础镜像拉下来、打回标准标签，再正常构建——**不需要改动 Docker 的全局配置**：

```bash
docker pull docker.m.daocloud.io/library/python:3.12-alpine
docker tag  docker.m.daocloud.io/library/python:3.12-alpine python:3.12-alpine
docker build -t report-portal-lab .
```

若实在无法构建镜像，也可以按「方式三」直接用本机 Python 跑，靶场逻辑完全一致。

> 在 **Windows 上**直接跑时，沙盒默认的 `/flag`、`/root` 会按当前盘符解析，
> 需要通过环境变量指到本机对应目录，例如：
> `$env:SANDBOX_READ_ROOTS = "<盘符>:\flag,<盘符>:\root"`（容器中使用默认值即可，无需设置）。
